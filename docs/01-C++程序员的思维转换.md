# C++ 程序员的思维转换表

> 你不需要"从零学编程"，你需要的是**把已知的概念映射到新领域**，再补上真正新的部分。
> 下面左边是你已经会的，右边是前端里对应的东西。

## 一、对应关系

| 你已经会的（C++） | 前端的对应物 | 关键差异 |
| --- | --- | --- |
| `main()` 入口 | `index.html` | **没有显式入口函数**。浏览器从 HTML 开始，一路解析下去 |
| 编译成机器码 | 源码直接交给浏览器解释/JIT | 没有"编译产物"给用户，用户拿到的是文本（或压缩后的文本） |
| `#include` / 链接 | `import` / ESM 模块 | 语义接近，但模块是异步加载的 |
| 类型系统（编译期检查） | TypeScript（可选的类型层） | JS 本身无类型，TS 只是构建时擦除的类型标注 |
| `std::vector` | 数组 `[]` | JS 数组是动态的、可混装类型 |
| `struct` / `class` | 对象字面量 `{}` / `class` | 一切都是对象，没有值/引用语义的严格区分（除了原始类型） |
| 手动内存管理、析构 | **GC 自动回收** | 没有 `delete`，但要注意"循环引用"和"闭包持有"导致的内存泄漏 |
| 指针 / 引用 `&` | 对象引用（隐式） | 传对象就是传引用，传数字/字符串/布尔是复制 |
| `nullptr` / UB | `null` / `undefined` | **两者不同**，且访问属性会抛异常（不是 UB，是可控的 TypeError） |
| `std::function` / lambda | 箭头函数 `() => {}` | 高频使用，是 JS 的一等公民 |
| Makefile / CMake | Vite / Astro 构建 | 职责类似，但通常零配置 |
| `std::cout` | `console.log` | 输出到浏览器控制台，不是终端 |
| 阻塞式同步代码 | 单线程 + 事件循环 | **这是最大的思维转变，见下** |

## 二、真正全新的三件事

### 1. 事件循环：单线程但不会卡死

C++ 里你可以 `while(true)` 阻塞，或者开线程。JS 只有**一个线程**，靠事件循环调度：

```
你的同步代码跑完 → 事件循环取出下一个任务（点击/网络返回/定时器）→ 执行 → 再取下一个
```

所以：
- **绝对不要写同步死循环**，会冻住整个页面。
- 耗时操作（网络、读文件、定时）一律是**异步**的，用 `await` 等待。
- `async/await` 本质是"把回调写成看起来同步的样子"，底层还是事件循环。

```js
// 看起来像同步，实际是"挂起当前函数，把控制权还给事件循环"
const res = await fetch('https://api.bgm.tv/...');
const data = await res.json();
```

### 2. 构建时 vs 运行时（Astro 的核心）

这是 Astro 新手最容易懵的地方。同一个文件里的代码，可能跑在两个完全不同的地方：

| | 在哪里跑 | 能做什么 | 用户能看到吗 |
| --- | --- | --- | --- |
| **构建时** frontmatter（`---` 之间） | 你电脑上的 Node.js | 读文件、连数据库、用密钥调 API | **看不到**，源码根本不发给用户 |
| **运行时** 模板里的 `<script>` / `client:*` 组件 | 用户的浏览器 | 操作 DOM、监听事件 | 看得到全部代码 |

**推论**：Bangumi 的 Token 必须放在构建时。放到浏览器端 = 把你的密钥公开发布出去。

### 3. 组件与"岛屿"

- 组件 ≈ 一个可以复用的、带参数的函数，返回一段 HTML。
- Astro 默认把组件**在构建时渲染成静态 HTML**，不发送任何 JS —— 这就是它快的原因。
- 只有当你需要**交互**（点击、拖拽、动画）时，才加 `client:load` 把它变成一座"岛屿"。

```astro
---
// 构建时执行
const posts = await getCollection('blog');
---
<ul>
  {posts.map(p => <li>{p.data.title}</li>)}   <!-- 构建时渲染成死 HTML -->
</ul>

<Pet client:load />   <!-- 这一块会在浏览器里活过来 -->
```

**桌宠必须用 `client:load`，文章列表不需要。** 想通这一点，你就理解了现代前端架构的一大半。

## 三、学习节奏建议

- **不要先啃完 JS 再动手。** 边做边补，遇到不懂的概念再查，效率高 3 倍。
- **每天收工前跑一次 `git commit`。** 这是你的存档点，也是最好的学习记录。
- **打开 DevTools 当主力工具**（F12）。看 Elements 面板 = 看实时 DOM；Console = 你的 REPL；Network = 看请求。
- **看不懂报错就整段贴给我。** 前端报错比 C++ 的模板报错友好得多。
